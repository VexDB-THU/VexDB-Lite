# 重复中心检查、过滤检索与业务适配验证

日期：2026-10-27。范围：用户明确要求的两项修复和后续不同业务形态、强过滤质量/速度测试。独立于已结束的过夜及候选补齐研究，不恢复或延长旧窗口。当前阶段为实现与正确性回归，正式计时前另冻结协议和源码。

## 修复内容

1. DuckDB不再无条件设置`skip_check_duplicate=true`。每次子向量聚类结束后，仍检查中心数量和非有限数；重复中心只有在该子向量输入的不同值数量不足所需中心数时允许。输入足够多样而中心意外重复时继续报错。保留PG适配层原有显式策略兼容，新增策略默认关闭。
2. 删除过滤查询“先全局ANN再按固定4倍或估计比例补候选”的改写。当前算子无法获知外层SQL过滤后还剩多少条，即使比例准确也不保证近邻与业务过滤独立。本轮让存在过滤的查询保留DuckDB自然的先过滤、再精确排序计划；不再承诺过滤ANN加速。无过滤的PQ图/原图路径保持原样。

过滤优先精确路径优先保证合法记录足够时返回足量结果。强过滤可能减少大量距离计算；弱过滤可能比近似索引慢，完整报告该代价。未来若增加过滤感知ANN，需要单独设计并验收，不通过更换另一个固定倍数绕过问题。

## 正确性回归

- 重复子向量、少于256种取值、小样本、全常量、部分子空间常量，以及高多样性却重复中心的异常；NaN/Inf和中心数量错误必须被拒绝。
- SQL过滤：0条、少于k、远离全局近邻但符合业务条件的子集；AND/OR/IN/NULL、参数变化、OFFSET、标量子查询向量、DML与保存重开。
- 强制低暴力阈值并核对计划，避免把旧4倍候选不足误当成正确结果；无过滤仍检查实际使用索引。
- 修改共享量化检查后，验证PG、DuckDB、SQLite上下文编译；接口兼容和本地回归不当成三个引擎的生产验收。

## 性能和质量验证

- 图像SIFT、文本DBpedia使用现有公共向量和已用开发代理查询；另加明确标注为模拟的商品/租户聚类数据，覆盖向量与类别相关的过滤。没有真实客户负载或新量化算法宣称。
- 过滤档覆盖约50%、1%、0.1%、0.01%，并补合法结果少于k及没有结果的边界；商品模拟另覆盖与近邻分布相关的业务类别。
- 对照保留旧原图、旧PQ图、旧精确SQL和新过滤优先精确SQL。同质量比较速度，低召回或少返回的快点不能算胜出。
- 每条查询从真实返回ID及独立原向量距离核对过滤集合中的top-k，记录不足返回、Recall@k和实际计划；重复/并列采用明确的距离边界规则。
- 正式计时用原生prepared SQL、包含执行/物化/取ID，保存逐请求时间。计划1/16/64连接、两个反序轮次；唯一查询数、遍次和有限运行期限在启动前冻结。报告共享宿主和排队延迟，不将回放或正确性测试当作QPS。
